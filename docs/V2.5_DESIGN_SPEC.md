# TinyDesk v2.5 设计规格书

> 版本: 1.0-draft
> 日期: 2026-08-03
> 状态: 实施中

---

## 一、概述

v2.5 引入「资料库」——一个独立于桌面卡片的长文档管理系统，专门处理资料整理。桌面便签、待办、重要日期维持 v2.0 全部行为不变。

### 核心原则

1. **桌面卡片 + 资料库各自独立**：卡片继续做快速记录，资料库做结构化长文档。
2. **存储分离**：资料库使用独立 SQLite，不触碰 `workspace.json`，v2.0 数据不受影响。
3. **离线原生**：零网络请求、无需账号，全文索引基于 SQLite FTS5。
4. **古风审美**：十二套无横线国风花笺 + 仿宋优先的中文排版，英文保持 Apple 系统字体。
5. **RTF/RTFD 为主格式**：复用已有 `RichTextDefaults` 的 NSAttributedString 管线。

### 不做的

- 不改为多 window 编辑器应用（资料库为单一窗口，三栏布局）
- 不引入云同步、账号系统
- 不修改现有 `workspace.json` schema
- 不在桌面卡片中嵌入长文档编辑
- 不内置字体文件（v2.5 首发仅使用系统字体回退）

### 3.2 SQLite 表结构

```sql
-- 目录
CREATE TABLE categories (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    sort_order INTEGER NOT NULL DEFAULT 0,
    icon_name TEXT,
    created_at TEXT NOT NULL
);

-- 标签
CREATE TABLE tags (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL UNIQUE,
    color_hex TEXT NOT NULL DEFAULT '#808080',
    created_at TEXT NOT NULL
);

-- 文档（SQLite 行 + 文件系统 RTFD 配对）
CREATE TABLE documents (
    id TEXT PRIMARY KEY,
    title TEXT NOT NULL DEFAULT '未命名文档',
    category_id TEXT REFERENCES categories(id) ON DELETE SET NULL,
    is_favorited INTEGER NOT NULL DEFAULT 0,
    paper_theme TEXT NOT NULL DEFAULT 'suJian',
    font_preset TEXT NOT NULL DEFAULT 'fangSong',
    word_count INTEGER NOT NULL DEFAULT 0,
    summary TEXT NOT NULL DEFAULT '',
    custom_cover_color_hex TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    deleted_at TEXT               -- NULL = 正常，非 NULL = 回收站
);

-- 文档-标签关联
CREATE TABLE document_tags (
    document_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    tag_id TEXT NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (document_id, tag_id)
);

-- FTS5 全文索引
CREATE VIRTUAL TABLE documents_fts USING fts5(
    title,
    body,          -- 从 RTFD 提取纯文本
    tags,          -- 关联标签名（空格分隔）
    category,      -- 关联目录名
    content='documents',
    content_rowid='rowid',
    tokenize='unicode61 remove_diacritics 2'
);

-- FTS 同步触发器（INSERT/UPDATE/DELETE 时自动维护）
-- ...（标准 FTS5 触发器模式）
```

### 3.4 回收站规则

- 删除文档时写入 `deleted_at` 而非物理删除
- 回收站显示所有 `deleted_at IS NOT NULL` 的文档，按删除时间倒序
- 保留 90 天，超期后台自动清理（下次启动资料库时触发）
- 手动"清空回收站"立即物理删除 RTFD 文件和 SQLite 行
- "恢复"时置 `deleted_at = NULL`

## 五、编辑器提炼与复用

当前 `RichTextEditor` + `RichTextEditorController` 约 600 行，已能处理粗体/斜体/下划线/删除线/颜色/清除格式/撤销/RTF 序列化。v2.5 需要将其从桌面便签的 `StickyCardContent` 中提炼出来，使其同时服务于资料库编辑器。

### 5.1 提炼方案

将 `RichTextEditor.swift` 中的以下组件提取为独立的可复用模块：

- `RichTextEditor`（`NSViewRepresentable`）→ 保持不变，已天然可复用
- `RichTextEditorController` → 保持不变，接受 `NSTextView` 连接
- `RichTextDefaults` → 扩展 `font(size:preset:)` 重载
- `RichTextFormattingToolbar` → 新增强：字体/字号/标题选择器

### 5.2 字体策略

```
中文首选: STFangsong (系统仿宋)
  ↓ 缺失时
中文降级: STSongti-SC (系统宋体)
  ↓ 缺失时
中文再次降级: PingFang SC

英文始终: -apple-system (San Francisco)
```

实现方式：使用 `NSFontDescriptor` 的 cascade list。

```swift
// RichTextDefaults 扩展
static func fangSongFont(size: CGFloat) -> NSFont {
    // 尝试 STFangsong
    if let fangSong = NSFont(name: "STFangsong", size: size) {
        return fangSong
    }
    // 降级宋体
    if let songTi = NSFont(name: "STSongti-SC", size: size) {
        return songTi
    }
    // 系统兜底
    return NSFont.systemFont(ofSize: size)
}

static func font(size: CGFloat, preset: FontPreset) -> NSFont {
    switch preset {
    case .fangSong: return fangSongFont(size: size)
    case .songTi:
        return NSFont(name: "STSongti-SC", size: size)
            ?? NSFont.systemFont(ofSize: size)
    case .system:
        return NSFont.systemFont(ofSize: size)
    }
}
```

**RTF 中的字体名**：序列化时仿宋字体名写为 `STFangsong`，英文段落保持 `-apple-system`。打开 RTF 时，若本地无对应字体，AppKit 自动走系统字体回退。

**关于内置字体文件**：不在 v2.5 首发加入。如需后续加入 FandolFang 等开源仿宋，先独立完成 SIL/OFL 许可证审查和归属文件。

### 6.2 主题实现


正文中的低对比度颜色使用 `NSLayoutManager` 临时前景色增强可读性，既不会污染 `NSAttributedString`，也不会改写 RTFD；PDF 在渲染副本中应用同一规则。

### 6.3 主题存储

主题只保存在文档元数据中（`documents.paper_theme`），**不写入 RTFD 文件**。文档本身的 NSAttributedString 不含纸张背景信息。PDF 导出时应用主题样式。

## 七、导入/导出

### 7.1 导入

| 格式 | 实现方式 | 保真度 |
|---|---|---|
| RTF | NSAttributedString 原生读取 | 完整保留粗体/斜体/颜色/下划线/图片 |
| RTFD | NSFileWrapper 读取 | 完整保留 + 图片附件 |
| TXT | 纯文本创建 | 无格式 |
| Markdown | NSAttributedString 从 Markdown 读取（`NSAttributedString.DocumentType.markdown`） | 粗体/斜体/标题/链接保留；表格和脚注可能丢失 |
| DOCX（兼容增强） | 先用样本验证 `NSAttributedString` 的 `docx` 读取能力 | 实验性 |

导入流程：
1. `NSOpenPanel` 选择文件
2. 读取为 `NSAttributedString`
3. 写入 `RichTextDefaults.rtfData()` → RTFD 文件
4. 插入 SQLite 文档行 + FTS 索引
5. 显示在文档列表中

Markdown 导入时弹出提示：「Markdown 导入可能丢失富文本样式（表格、脚注、自定义样式等），建议复杂文档使用 RTF 格式。」

### 7.2 导出

| 格式 | 实现方式 |
|---|---|
| RTF | 直接从 RTFD 提取 `TXT.rtf` |
| TXT | `attributedString.string` 写文件 |
| Markdown | `NSAttributedString` 转换（`NSAttributedString.DocumentType.markdown`） |
| PDF | `NSPrintOperation` → PDF data |
| 资料库备份包 | ZIP 文件（参见 3.5） |

Markdown 导出时弹出提示：「导出为 Markdown 可能丢失富文本样式（颜色、图片、自定义字体等），如需完整保留建议导出为 RTF 或 PDF。」

PDF 导出使用纸张主题渲染背景：
```swift
// LibraryPDFRenderer
func render(document: LibraryDocument, attributedString: NSAttributedString, theme: PaperTheme) -> Data {
    let printInfo = NSPrintInfo.shared
    let printOp = NSPrintOperation(
        view: paperBackedTextView(attributedString, theme),
        printInfo: printInfo
    )
    // configure, run, extract PDF data
}
```

### 7.3 文件类型注册

在 `Info.plist` 中声明文档类型（让 Finder 支持"打开方式"→ TinyDesk）：
- `com.kai.tinydesk.library-document` → RTF, RTFD
- 沙盒权限声明 `com.apple.security.files.user-selected.read-write`

## 八、存储与兼容性

### 8.1 LibraryStore

```swift
@MainActor
final class LibraryStore: ObservableObject {
    // SQLite 连接
    private var db: OpaquePointer?

    // 已发布的 UI 状态
    @Published var categories: [LibraryCategory] = []
    @Published var tags: [LibraryTag] = []
    @Published var documents: [LibraryDocument] = []
    @Published var searchResults: [LibrarySearchResult] = []
    @Published var selectedDocumentID: UUID?
    @Published var activeCategoryFilter: UUID?       // nil = 全部
    @Published var activeTagFilters: [UUID] = []
    @Published var searchQuery: String = ""
    @Published var storageMessage: String?

    // 初始化：创建 SQLite 表 + FTS 索引
    // 保存：writeDocument(_:rtfdData:) → 写文件 + UPSERT SQLite + FTS
    // 删除：softDelete(_:) → SET deleted_at
    // 清空回收站：purgeTrash() → DELETE + 删除 RTFD 文件
    // 搜索：search(_:) → FTS5 SELECT
}
```

### 8.2 与 v2.0 的隔离保证

- `LibraryStore` 只读写 `~Library/library.db` 和 `~Library/documents/`
- `DesktopWorkspaceStore` 只读写 `workspace.json`
- 两者不共享任何数据库连接或文件路径
- v2.0 的 `TinyDeskWorkspace` schema 不变（仍为 schema 3）
- 桌面卡片新增 `kind: .deskRef` 时附带可选字段，旧版遇到未知 kind 也能安全跳过

### 8.3 数据库迁移

SQLite schema 版本记录在 `PRAGMA user_version`。首次启动时建表并设版本为 1。后续升级时在 `LibraryStore.init()` 中按版本号执行迁移 SQL。

## 十、SQLite 依赖声明

TinyDesk 不引入第三方 Swift Package。macOS 自带 `libsqlite3.tbd`，在 `project.yml` 中新增：

```yaml
settings:
  base:
    OTHER_LINKER_FLAGS: -lsqlite3
```

TinyDeskCore 中封装 C SQLite3 API 为 Swift 友好接口。

## 十一、参考项目分析

**Achilng/floral-notepaper（花笺）** 是一个采用 Tauri 2 + React 的 MIT 开源笔记应用。TinyDesk 只参考其快速记录、资料整理与花笺语义，使用原生 Swift/AppKit 独立实现，不引入其跨平台运行时，也不复制图片素材。

| 花笺元素 | TinyDesk 对应 |
|---|---|
| 纸张纹理背景 | `PaperBackground` 十二套无横线主题 |
| 仿宋/楷体字体 | `STFangsong` 系统仿宋 + 字体回退 |
| 竖排文本（花笺特色） | **v2.5 不实现**。NSTextView 的竖排支持需要 `NSTextLayoutManager` 自定义布局，成本高，留到 v2.6 |
| 印章/落款 | 使用纯矢量淡印作为纸面装饰，不进入正文内容 |
| 毛笔字体标题 | **不引入**，涉及字体版权 |
| 花鸟/山水装饰 | 可通过纸张主题的纹理层实现简化版 |
| 全文搜索 | SQLite FTS5 |
| 分类/标签 | LibraryCategory / LibraryTag |

## 十二、验收标准

1. **离线运行**：关闭网络后，资料库全部功能正常（新建、编辑、搜索、导入导出、备份恢复）。
2. **长文档管理**：可创建、编辑、保存 > 10,000 字的文档，格式不丢失。
3. **全文检索**：输入关键词可按标题、正文、标签、目录找到对应文档。
4. **RTF 格式保真**：导入 RTF → 编辑 → 导出 RTF，粗体/斜体/颜色/下划线保持不变。
5. **资料库备份恢复**：导出 ZIP 备份包 → 清空资料库 → 导入备份包，所有文档完整恢复。
6. **v2.0 不发生回归**：所有现有 `workspace.json` 数据（便签、待办、重要日期、农历、系统日历关联、富文本）在 v2.5 下完整可用。
7. **桌面摘要卡片**：可创建、显示摘要、双击打开资料库、从桌面移除而不删除文档。
8. **花笺主题**：十二套主题可切换，正文与 PDF 在所有底色上保持可读且不改写原始富文本。
